# Multi-Project Manager

سامانهٔ دوزبانهٔ فارسی/انگلیسی برای معرفی فعالیت‌های مجموعه و مدیریت پروژه‌های صادرات، سردخانه، همکاری با مراکز سورتینگ، ساخت‌وساز و اجارهٔ املاک. نشان و نام شرکت فعلاً موقت هستند.

## قابلیت‌ها

- ویترین عمومی واکنش‌گرا و داشبورد پروژه‌ها با جست‌وجو، فیلتر، جزئیات، ایجاد و ویرایش.
- ورود با ایمیل و رمز عبور، نشست قابل ابطال و ثبت‌نام بدون حساب Manus.
- ثبت‌نام عمومی بدون تأیید ایمیل یا مدیر، حساب فعال می‌سازد؛ هر کاربر فعال به همهٔ پروژه‌ها دسترسی دارد. پیش از استفاده از داده‌های واقعی، دسترسی عمومی را محدود و سیاست امنیتی را بازبینی کنید.
- پنل مدیر برای ایجاد کاربر، ویرایش نام، نقش، وضعیت، و تنظیم رمز جدید. فقط مدیر می‌تواند کاربران را مدیریت کند. حداقل یک مدیر فعال باید باقی بماند.
- ثبت و فهرست طرف‌حساب‌ها (تأمین‌کننده، مشتری، واسطه) و محموله‌ها در پروژهٔ صادراتی، با API مبتنی بر کد پروژه و ذخیره در PostgreSQL.
- API با Go، دیتابیس PostgreSQL، migrationهای نسخه‌بندی‌شده، Docker Compose و پیکربندی Vercel.

**محدودیت مهم:** کاربران فعال، چه مدیر و چه کاربر عادی، به همهٔ پروژه‌های مشترک دسترسی دارند؛ هنوز مجوز جداگانه برای هر پروژه وجود ندارد. دفترکل و امکانات مالی، گزارش حسابرسی و بازیابی رمز از طریق ایمیل پیاده‌سازی نشده‌اند. برای رمز فراموش‌شده باید به مدیر مراجعه شود. قبل از ورود داده‌های واقعی مالی، بازبینی امنیت، backup و نیازمندی‌های دسترسی لازم است.

## ساختار

- `frontend/`: Next.js، React، TypeScript و Tailwind CSS.
- `backend/`: API ماژولار Go، ورود محلی، کاربران و پروژه‌ها.
- `docker-compose.yml`: اجرای وب، API و PostgreSQL با volume پایدار.
- `vercel.json`: مسیریابی frontend و API کانتینری.
- [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md): تنظیم Vercel یا سرور داخلی، مدیر اولیه و پشتیبان‌گیری.

## اجرا و آزمایش محلی

Node.js 20.9+، pnpm 11 و Go 1.22+ لازم است. برای نمونهٔ موقت، ابتدا مدیر نمونه را فقط در محیط محلی تعریف کنید:

```bash
pnpm install --frozen-lockfile
export BOOTSTRAP_ADMIN_EMAIL=admin@example.test
read -s -p 'Temporary local admin password: ' BOOTSTRAP_ADMIN_PASSWORD; export BOOTSTRAP_ADMIN_PASSWORD; echo
pnpm dev
```

رمز باید ۴ تا ۷۲ بایت UTF-8 باشد؛ برای محیط واقعی یک رمز قوی‌تر انتخاب کنید. در این حالت، بدون `DATABASE_URL` و فقط خارج از production، داده‌های پروژه، صادرات، کاربر و نشست موقتی و حافظه‌ای‌اند و با restart پاک می‌شوند. API در پورت 8080 و frontend در پورت 3000 اجرا می‌شوند. مبدأ پیش‌فرض محلی `http://localhost:3000` است؛ برای مبدأ دیگر، `PUBLIC_APP_ORIGIN` را دقیقاً تنظیم کنید.

```bash
pnpm typecheck
pnpm build:web
cd backend && go test ./... && go vet ./...
```

برای آزمون یکپارچهٔ PostgreSQL، `TEST_DATABASE_URL` را فقط به یک دیتابیس **آزمایشی خالی** بدهید. از دیتابیس واقعی یا اطلاعات واقعی برای تست استفاده نکنید.

## Production

Production بدون `DATABASE_URL` پایدار، مبدأ دقیق HTTPS، و مدیر فعال راه نمی‌افتد. در اولین راه‌اندازی دیتابیس خالی، `BOOTSTRAP_ADMIN_EMAIL` و `BOOTSTRAP_ADMIN_PASSWORD` را تنها در محیط سرور تنظیم کنید. پس از ساخته‌شدن مدیر، می‌توان این دو متغیر را حذف کرد؛ راه‌اندازی دوبارهٔ برنامه، حساب موجود را بازنویسی نمی‌کند. اطلاعات محرمانه را هرگز در Git، `NEXT_PUBLIC_*` یا پیام عمومی قرار ندهید. جزئیات و مراحل Vercel/Compose در [راهنمای استقرار](docs/DEPLOYMENT.md) آمده‌اند.

اتصال مخزن و وضعیت deployment در Vercel باید در حساب مربوط بررسی شوند. برای اجرای واقعی، یک PostgreSQL مستقل و پایدار، متغیرهای محیطی، حساب مدیر و backup لازم‌اند. وضعیت build موفق به‌تنهایی به معنی کارکرد دیتابیس و ورود نیست. راه‌اندازی روی دیتابیس قدیمی می‌تواند migration قبلی 004 را اجرا کند که حساب‌های pending و نشست‌هایشان را حذف می‌کند؛ پیش از ارتقا وضعیت migration و backup/restore را بررسی کنید.
